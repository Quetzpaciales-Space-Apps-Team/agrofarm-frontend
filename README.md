# agrofarm-frontend

React + Vite single page app: a landing page that explains the project, then a five-step flow (your farm, your data, try a season, best crops, weather) with maps, scenario simulation and rotation comparison (service `frontend`).

Part of AgroFarm, a crop growth and rotation simulator for farmers. The tool supports decisions. It never replaces farmers or local agronomists.

## What the app does

1. **Landing page.** Explains the project in plain words: a hero, a scroll story that moves from the field to one maize ear, how it works, the decisions it helps with, the crops it compares, and the team with links to the four repositories.
2. **My farm.** Size, what is planted, and a map of the farm.
3. **Add your data.** Upload a CSV or GeoJSON file and read what was accepted.
4. **Try a season.** Move rainfall, temperature and the El Nino or La Nina pattern and see the likely range of change in yield, with the key result in a highlighted card.
5. **Best crops.** Compare crop rotations with your priorities. Each strategy opens a screen of its own: photos of its crops, what happens in each season, the farm map once per season, and all the evidence and risks.
6. **Weather.** Rain and temperature near the farm, with a plain summary first.

Every inner page starts with one plain sentence and three things to do, and ends with a link to the next step. More detail, and the reasons behind the choices: [`docs/ui-and-landing.md`](docs/ui-and-landing.md).

## Development Setup

- **Node.js:** `>=20`
- **Package manager:** `npm` (committed lockfile: `package-lock.json`)

```bash
npm ci
cp .env.example .env
make dev        # Start local Vite dev server
make check      # Run lint, typecheck and tests
make build      # Build production bundle
```

`make check` runs `npm run lint`, which is `eslint . && prettier --check .` on the **whole repository** (not only `src`), exactly as CI does. A file outside `src` that is not formatted, for example a Markdown file in `public/`, turns the CI lint job red. CI also runs the build, a Docker build, a Trivy scan and the repository policy checks.

### Running without the backend (mocks)

The app reads `/config.json` at start (`apiBaseUrl`, `useMocks`). `public/config.json` ships with
`useMocks: true`, so `make dev` serves the typed MSW handlers from `src/test/handlers.ts` through a
service worker (lazy-loaded, not part of the main bundle). In the container, `docker/40-generate-config.sh`
overwrites the file from `API_BASE_URL` and `USE_MOCKS`. The worker script `public/mockServiceWorker.js`
is generated by `npx msw init public/ --save=false`; commit the output again after upgrading `msw`.
Choose "Try the demo" on the landing view to start a guest session (`POST /v1/auth/demo`).

## The short version of the rules

1. Everything is written in English.
2. Tests first (TDD). CI must be green.
3. Branch from `develop`, open a pull request into `develop`. Nobody pushes to `develop` or `main` directly.
4. `develop` deploys to staging. `main` deploys to production (no manual approval is configured yet, see Deployed environments). Only `develop` and `main` exist as long-lived branches; delete a feature branch after its pull request is merged.
5. One task, one branch, one pull request.
